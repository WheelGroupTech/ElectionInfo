# ElectionExplorer.Package — MSIX packaging for the Microsoft Store

Windows Application Packaging Project (`.wapproj`) that wraps the full-trust
Win32 app `ElectionExplorer.exe` as an **MSIX** and produces a single
**x64 + ARM64** bundle for upload to the Microsoft Store.

The app itself needs no source changes to be packaged: it is static-CRT (`/MT`,
no VCRedist dependency), runs `asInvoker`, and stores its options in
`HKEY_CURRENT_USER` (transparently virtualized inside an MSIX package).

## Partner Center identity

The identity in [`Package.appxmanifest`](Package.appxmanifest) is set to the
values assigned by Partner Center for this app:

| Manifest field | Value |
|---|---|
| `Identity/@Name` | `WheelGroupTech.ElectionExplorer` |
| `Identity/@Publisher` | `CN=19C9DED9-26A0-4883-97F5-C2A81BF980D6` |
| `Properties/PublisherDisplayName` | `WheelGroupTech` |

If the Store listing identity ever changes, update these to match or the upload
is rejected.

## Build the Store upload bundle

**Visual Studio:** right-click the project → **Publish → Create App Packages →
Microsoft Store**, sign in, select **x64** and **ARM64**.

**Command line:**

```bash
msbuild ElectionExplorer.Package\ElectionExplorer.Package.wapproj /p:Configuration=Release /p:Platform=x64 /p:AppxBundle=Always /p:AppxBundlePlatforms="x64|arm64" /p:UapAppxPackageBuildMode=StoreUpload
```

Output (git-ignored):

```
Applications/Build/msix/ElectionExplorer.Package_<version>_x64_arm64_bundle.msixupload
```

Upload that `.msixupload` in Partner Center. **Do not sign it** — the Store signs
the upload with its own certificate.

## Logo assets

`Images\*.png` are generated by
[`tools/generate-assets.ps1`](tools/generate-assets.ps1) from
[`tools/logo-source.png`](tools/logo-source.png) (a 1152×1712 rendering of the app
logo with a transparent background):

```bash
pwsh -File tools\generate-assets.ps1
```

`logo-source.png` has a real alpha channel, so the generator crops the logo to
its content box and renders each asset on a **transparent** canvas (transparent
tiles and taskbar/Start icons). The manifest `BackgroundColor` is `#FFFFFF`; it
shows through behind the logo on plated tiles and the splash screen — change it to
a brand color if preferred.

The generator auto-detects the source: an opaque source is instead rendered on
its sampled background color. A different source can be passed with
`-SourcePng path\to\logo.png`. (No 256px small-logo target size is emitted: it can
exceed the 200 KB per-asset limit.)

### Application icon (res/app.ico)

The Win32 app icon is generated from the same `logo-source.png` by
[`tools/generate-icon.ps1`](tools/generate-icon.ps1) (requires ImageMagick 7+):

```bash
pwsh -File tools\generate-icon.ps1
```

It writes a multi-resolution transparent `..\ElectionExplorer\res\app.ico`
(16/24/32/48/64/128/256) using a **square crop** of the portrait logo (trim
margins, center-crop to square, inset slightly). `app.ico` drives the window
title-bar icon, Alt+Tab, and the Explorer icon of the `.exe`; the Store tiles use
the `Images\` assets above. Rebuild the app after regenerating so the new icon is
compiled in.

## Local sideload testing (optional)

Store upload needs no signature, but to install locally you must sign with a
certificate whose subject equals `Identity/@Publisher`:

```powershell
# One-time: create a self-signed cert matching the manifest Publisher.
$cert = New-SelfSignedCertificate -Type Custom -Subject "CN=WheelGroupTech" `
  -KeyUsage DigitalSignature -FriendlyName "ElectionExplorer Dev" `
  -CertStoreLocation "Cert:\CurrentUser\My" `
  -TextExtension @("2.5.29.37={text}1.3.6.1.5.5.7.3.3", "2.5.29.19={text}")

# Build a sideload package (not StoreUpload), then sign and install the .msix:
signtool sign /fd SHA256 /a /f mycert.pfx /p <pwd> path\to\ElectionExplorer.Package_<ver>_x64.msix
Add-AppxPackage path\to\ElectionExplorer.Package_<ver>_x64.msix
```

## Versioning

Keep the package `Version` in `Package.appxmanifest` in sync with the app version
in `res/ElectionExplorer.rc` / `res/app.manifest` (currently **1.0.1.0**). The
Store requires the **revision** (4th) field to be `0`.

## Maintainer notes / gotchas

- The DesktopBridge targets ignore the repo-wide `OutDir` from
  `Directory.Build.props`; that override is scoped to non-`.wapproj` projects
  (overriding `OutDir` here breaks payload harvest, APPX0703). Final packages
  are redirected to `Build/msix/` via `AppxPackageDir`; intermediate `bin/` and
  `obj/` stay under this project (git-ignored).
- Logo assets are declared as `<Content>` with `<Link>` (not `<Image>`), which is
  what the DesktopBridge targets harvest into the package payload.
- `Directory.Build.props` must not define a property literally named `AppConfig`
  (reserved by MSBuild) — see the note there.
